## 3. How to use this pack

1. Read `08-source-register.md`. Nothing in this pack has been verified against a
   first-hand copy of a SAHPRA document (see §5). Download and check the current
   documents before anything is sent to the client or to SAHPRA.
2. Read `01-regulatory-strategy-memo.md`. Decisions D1 (DL02 + DL03) and D2 (five products,
   complete range) are settled; **D3, the responsible person, is the only one still open and
   is the longest lead item.** Note §4.1 — selling to retailers carries obligations beyond
   the extra licence.
3. Issue `03-client-information-request.md` to the client. The data it collects is on the
   critical path — the application cannot be drafted without it.
4. Populate `02-product-schedule.md` as data arrives.
5. Work `06-qms-sop-register.md` in parallel; the SOP set is usually the longest lead item
   after the responsible person appointment.
6. Assemble per `04-application-content-guide.md` and submit per `07-fees-timelines-submission.md`.

## 4. Confidentiality — read before adding anything to this folder

**This repository is public on GitHub** (`MuendoE/Biz-Sols`) and the Firebase Hosting
configuration publishes the repository root to the Alpha CR Solutions website. This folder
has been added to the `ignore` list in `firebase.json` so that it is **not** deployed to the
website, but that does not make it private — the files remain publicly readable on GitHub.

Accordingly, this pack deliberately contains **no** client-identifying information, no
personal data, no supplier or pricing information and no document images. It is written as
a working template with placeholders.

**Do not** commit the completed application, the client's name, the responsible person's
registration details, manufacturer agreements, GMP certificates or any filled-in version of
the information request to this repository. Keep those in the client's confidential file.

## 5. Verification caveat

This pack was drafted in an environment whose network policy blocked outbound access to
`sahpra.org.za` and to the legal databases carrying the Medicines Act schedules. Guideline
numbers, licence type codes, fees, document requirements and the scheduling position of
selenium were established from search-engine summaries of those documents, **not** from the
documents themselves. Every such point is flagged `[VERIFY]` in the text and listed in
`08-source-register.md`.

Treat the pack as a correct structure and a correct set of questions, with citations that
must be confirmed before use.
